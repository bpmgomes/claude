# Revisão de segurança · AF-09

Veredito: APROVADO. Nenhum problema de gravidade alta ou média. `npm audit`: 0 vulnerabilidades. 850 testes passando; `npm run perf` p75 ≈ 510 ms; `npm run test:e2e` 28/28.

## Problemas encontrados (pendentes, todos de gravidade baixa)

1. URLs malformadas (`frameworkErrors`) ficam sem rate limit e sem os cabeçalhos do helmet (HSTS, CORP, COOP); o JSON 400 desses erros sai sem `nosniff`/CSP. Completar cabeçalhos em `sendHtml` e no JSON, e opcionalmente um contador barato.
2. O contador do 404 de fallback também vale para `/api/*`, `/media/*` e outros métodos. Aplicar o limite só quando `wantsHtmlNotFound(request)` ou usar bucket separado.
3. Três contadores independentes por IP (`/:slug`, `/:slug/`, fallback): ~360 req/min por IP, facilitando raspagem de endereço e telefone. Compartilhar o contador entre as três rotas.
4. O 404 de fallback ainda lê a sessão do dono (o `setNotFoundHandler` não tem `config.publicRoute`). Pular a sessão também nesse caminho.
5. Informativo: `slug-availability` responde `TAKEN` para slug em quarentena (decisão de design).
6. Informativo: redirects 301 saem com a CSP padrão do helmet.

## Ressalvas do QA (desempenho)

- A medição de 2 s usa um logo sintético; com logo fotográfico o p75 sobe para ~1,1 s e no pior caso ~1,4 s (ainda dentro da meta).
- Fotos de profissionais são PNG 256 px (~155 KB cada) exibidas a 64 px; 10 fotos somam 1,7 MB (~8,8 s em 4G rolando a página). Sugestão futura: variante menor ou WebP.
- Fotos sempre `loading="lazy"`, mesmo quando estão na primeira dobra.
