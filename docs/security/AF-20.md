## Problemas encontrados

1. **Médio (corrigido na documentação):** com `pull_request`, o CI roda o `ci.yml` do próprio PR; quem abre o PR pode adulterar o workflow ou criar outro job `ci-ok` verde. O passo a passo do README agora pede origem fixa em "GitHub Actions", aprovação obrigatória com descarte de aprovações antigas, CODEOWNERS para `/.github/` e manifestos, ou "Require workflows to pass" em rulesets. Depende do dono do repositório.
2. Baixo: actions fixadas por tag maior, não por SHA, e versões mais recentes não conferidas online. Conferir as tags e, num item futuro, adotar Dependabot para `github-actions` e fixar por SHA.
3. Baixo: Playwright instalado com `npm install --no-save playwright@1.63.0`, sem hash versionado. Aceitável; para endurecer, um lockfile separado em `ci/playwright/` com `npm ci`.
4. Baixo: o processo filho do smoke herda o ambiente inteiro (`scripts/smoke.js:77`). Opcional: lista de permissões de variáveis.
5. Informativo: o segredo efêmero fica no `GITHUB_ENV` do job `build-check` inteiro. Impacto nulo (aleatório, de uso único).
