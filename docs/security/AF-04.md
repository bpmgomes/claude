# Revisão de segurança · AF-04

Veredito: APROVADO. Nenhum problema de gravidade alta ou média. `npm audit`: 0 vulnerabilidades. 1260 testes passando (também com `TZ=Asia/Tokyo`); `npm run test:e2e` 46/46; `npm run perf` 2/2.

Confirmado: `findOrCreate` não revela se o e-mail já existia nem devolve dados guardados; `INSERT ... ON CONFLICT DO NOTHING` nunca sobrescreve; consultas filtradas por `business_id`; validação sem eco da entrada e com recusa de CR/LF; JS público só com `textContent`; `no-store` em `/api/*` decidido pela rota casada (inclusive com percent-encoding); `credentials: 'omit'` no fetch público.

Também resolve o item 5 de docs/security/AF-16.md (`/api/*` sem `no-store`).

## Problemas encontrados (pendentes, todos de gravidade baixa)

1. Redact de log cobre só a chave `customer` (até 4 níveis). `snapshot: { email }` e `input: { email }` saem em texto puro. Incluir `snapshot`/`*.snapshot` (ou mascarar `name`, `phone`, `email`) e testar que o retorno de `findOrCreate` não é logado. **Tratar no AF-11.**
2. E-mail sem normalização NFC (`normalizeEmail` em `src/shared/validation.js`): o mesmo endereço em forma composta e decomposta vira dois clientes; a regex aceita `<`, `>`, `"` e homógrafos. Aplicar `.normalize('NFC')` ou restringir a parte local a ASCII.
3. Nome e e-mail aceitam metacaracteres de HTML e de planilha (`<img ...>`, `=HYPERLINK(...)`). Tratar como entrada não confiável no AF-11, AF-14 e AF-18: escapar sempre na agenda e no e-mail, e neutralizar `= + - @` em exportações CSV.
4. Diferença de tempo entre criar e reaproveitar cliente pode, em tese, revelar se um e-mail existe. **Tratar no AF-11:** manter rate limit por IP e o mesmo caminho de código nos dois casos.

## Ressalvas do QA

- 1ª rodada REPROVADA: `GET /%61pi/business` devolvia dados do dono sem `no-store` (o hook olhava a URL bruta). Corrigido com `src/http/api-path.js`; 2ª rodada APROVADA.
- 404 de rota inexistente pedida em forma absoluta (`GET http://host/api/nao-existe`) recebe o 404 HTML com cache público. Não expõe dados.
- 404 JSON de POST fora de `/api/` sai sem `Cache-Control`. Fora do escopo; sem dados.
- O caminho de envio do formulário (`aria-live="off"` no campo focado) ainda é inalcançável (botão desabilitado até o AF-11) e não tem teste.
